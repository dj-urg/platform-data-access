Chapter 9 · The wider landscape

More platforms

The big six aren't the whole field: the networks that are open by design, a VLOP with a documented researcher route, and the rest of the landscape in brief.

Bluesky — open by design

Everything on Bluesky is public by design: there are no private accounts, and the network's entire activity is available without application, approval or fees. Three doors exist. The full firehose — the AT Protocol relay stream (com.atproto.sync.subscribeRepos) — carries every public event on the network. Jetstream serves the same stream as friendlier, filtered JSON (by collection or account). And a normal HTTP API returns public profiles, posts, threads, likes and follows with no authentication at all. Since August 2026 the infrastructure is documented at bsky.network (“Bluesky Protocol Services”), with the endpoint reference at endpoints.bsky.app.

For historical data, Jetstream v2's Network Replay (added August 2026) replays the full network archive before handing over to the live stream. It is the one metered element in the pipeline: replay requires a free API key created from your Bluesky account and is billed by download volume, while the live tail stays open and keyless — and everything is open source and self-hostable. In practice, the atproto Python SDK is the standard library, and 4CAT collects from Bluesky natively. Bluesky reported roughly 46 million registered accounts by mid-2026; active use is considerably lower, so mind the registered-versus-active distinction when sampling.

Public by design ≠ consent to be studied

Bluesky is not a designated VLOP, so no DSA route exists — none is needed. But openness cuts both ways: a one-million-post dataset published on Hugging Face in November 2024 was withdrawn within days after user backlash (404 Media). Pseudonymise, honour deletions, and see Failla & Rossetti (2024) for a careful template.

Wikipedia and Wikimedia

Rarely included in platform guides, yet heavily used across the social sciences (edit histories, talk pages, pageviews around events) — and everything is open. The Wikimedia APIs (the Action API, the REST APIs, the Analytics/pageviews API and the EventStreams live firehose at stream.wikimedia.org) need no key for basic use. A descriptive User-Agent header with contact details is required — and it pays: under the rate limits introduced in 2026, identified clients (a compliant User-Agent, or authenticated requests) get roughly 200 requests/minute against 10/minute for anonymous traffic (the limits are marked experimental, so check the live policy).

Complete public database dumps are free (note: the classic XML dumps are being sunset in January 2027 in favour of the new MediaWiki Content File Exports), and Wikimedia Enterprise offers a free tier anyone can register for: a Snapshot API with monthly updates and an on-demand allowance of 50,000 requests/month (the realtime API is paid). Wikipedia is itself a designated VLOP, so DSA Art. 40 applies — though the open infrastructure already exceeds it in practice. The Foundation's research portal is research.wikimedia.org.

Snapchat

Snapchat is a designated VLOP with documented researcher-access instructions — relevant for youth and visual-culture research. Under Art. 40(12), email DSA-Researcher-Access@snapchat.com with your institution, the data and timeframe requested, purpose, methodology, funding sources and confirmation of non-commercial use (instructions). The data catalogue covers Spotlight content and comments, public Story and Map Story content, and public profile data. There is no API: approved requests are fulfilled manually, as a PDF or a protected cloud-storage link. For non-public data, apply through the EC Data Access Portal; Snap's DSC is the Dutch regulator. No successful fulfilments have been publicly documented yet — plan accordingly.

In brief: the rest of the field

  • Mastodon / the Fediverse. Each instance exposes the open Mastodon API (public timelines are usually readable without a token, though instances can switch this off; the default limit is 300 requests per 5 minutes). There is no gatekeeper — but research norms are stricter than the openness suggests: instance rules differ, several communities explicitly object to scraping, and a 2020 Mastodon dataset was withdrawn after a community open letter. Ask instances where feasible, and never republish identifiable content.
  • Pinterest. VLOP. A Researchers Intake Form handles Art. 40(12) requests for public data (no API; terms shared after approval; no published outcomes yet). Zeeschuimer captures Pinterest while you browse.
  • LinkedIn. VLOP. A beta Researcher Access Program exists but currently accepts mainly ads-related requests — there is no general public research API. The public Ad Library needs no application.
  • Bing. VLOSE. Microsoft's DSA Qualified Researcher Program provides anonymised search-query datasets, applied for through the EC Data Access Portal.
  • Google beyond YouTube. Search, Maps, Play and Shopping are covered by the Google Researcher Program; Google Trends has a separate API application.
  • Twitch. Not a VLOP; no researcher program. The self-service Helix API covers stream metadata, VOD metadata and clips; live chat is captured via EventSub/IRC, but there is no official historical-chat endpoint. A 2024 US congressional letter urged Twitch (and eight other companies) to open researcher access voluntarily.
  • Discord. No research access at all: no public-content API, and bots only work inside servers they are invited to. The same 2024 congressional letter batch went to Discord, and a 2025 academic scrape of two billion messages from public servers drew sharp privacy criticism — treat Discord research as human-subjects territory.
