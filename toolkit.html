Tools for collecting platform data

Three ways to collect data for research: the Methlab 4CAT instance, which connects to platform APIs; the Zeeschuimer browser extension, which records data while you browse; and data donation, in which participants share their own data exports.

4CAT — the Methlab instance at 4cat.vub.be

4CAT (Digital Methods Initiative, University of Amsterdam; Peeters & Hagen, 2022) is an open-source, web-based tool for collecting and analysing social media data. Each collection and analysis step is recorded, so results can be traced and reproduced. The current release is v1.57 (September 2026).

Methlab runs a shared 4CAT instance at 4cat.vub.be. The instance connects to the following platform APIs, so data can be collected through the 4CAT interface without writing code.

Zeeschuimer — recording data while browsing

For platforms without an API connector in 4CAT, or where the API is closed or has a low quota, Zeeschuimer offers a second method of collection. It is a Firefox extension by the same developers (v1.14.3, September 2026) that records the data a platform’s website loads while you browse. It currently supports 12 platforms (table below) and sends the recorded data to a 4CAT instance (including the Methlab one) or saves it as NDJSON or CSV files. It is commonly used where APIs are closed (Instagram) or limited (TikTok). Because the data is what a logged-in user saw, the collection also documents that user’s perspective.

Web scraping

Zeeschuimer is a form of web scraping, and the same rules apply to any scraper you write yourself. Scraping publicly accessible data for academic research is not prohibited by EU law as such, and the GDPR’s research provisions accommodate it (purpose-compatibility presumption, Art. 89 safeguards) — provided you still meet GDPR’s principles: a lawful basis, minimisation, security, and a DPIA where required. DSA Art. 40(12) strengthens the position against VLOPs, and the Commission’s 2025 decision against X treated terms banning researcher scraping of public data as part of X’s non-compliance. The residual tension is contractual: platform terms typically forbid automated collection, and breach risks account suspension or legal letters rather than criminal liability. Weigh public interest, minimisation and researcher safety with your ethics committee before scraping (Brown et al., 2024; Mancosu & Vegetti, 2020).

Data donation — access through participants’ own data rights

Under GDPR Articles 15 and 20, every platform must give users a machine-readable export of their own data. Data donation studies recruit participants who download that package and donate a filtered subset — the only way to obtain watch histories, feeds and exposure data that no API or browser capture provides, and it is based on the participant’s consent (Boeschoten et al., 2023; see also Ausloos & Veale, 2020, on researching with data rights).

Planned: Methlab is looking into hosting the Data Donation Module (DDM) from the University of Zurich’s Data Donation Lab in the same way as 4CAT, as a shared instance that researchers log into. DDM is an open-source web application in which researchers create, manage and monitor donation projects through a graphical interface; uploads are processed on the participant’s own device and only transmitted after explicit informed consent, and projects can be combined with the built-in questionnaire. Until that instance exists, an established alternative is datadonation.eu (the Digital Data Donation Infrastructure, D3I — now an ODISSEI service, with VU Amsterdam among the partners) built on the open-source Port software, which also processes the data on the participant’s own device.
